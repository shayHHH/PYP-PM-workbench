# 08 · Web 端后台 UI 风格规范

> 实现见 `assets/css/tokens.css`（设计变量）、`layout.css`（骨架）、`components.css`（组件）、`print.css`（打印）。
>
> 一句话概括风格：**信息密度优先的企业级 B 端后台**——13px 基准字号、6px 圆角、极浅阴影、无装饰性动效；颜色只用来表达状态，不用来做装饰。

---

## 一、设计原则

| # | 原则 | 具体落法 |
|---|---|---|
| 1 | **密度优先于呼吸感** | 基准字号 13px（`--f-base`）、行高 1.55；表格降一档到 12px（`--f-sm`），单元格 `padding:8px 12px`，实际行高约 35px。同屏放得下 20 行数据比"看起来舒服"更重要——用户是每天用 6 小时的专业角色，不是首次访问的访客。 |
| 2 | **颜色是语义不是装饰** | 全站只有 7 种语义色（done / doing / plan / warn / danger / idle / cyan），每种都对应明确的业务状态。不存在"为了好看加个渐变"的颜色。 |
| 3 | **同一设计系统，两种气质** | 角色差异**只通过 `--c-accent` 系列 5 个变量**表达。组件、间距、字号、圆角、阴影完全共用。 |
| 4 | **动效只服务于功能** | 只保留 120~220ms 的状态过渡（悬停、展开、抽屉滑入）。没有入场动画、没有数字滚动、没有骨架屏闪烁。 |
| 5 | **零外部依赖** | 无 Web Font、无图标字体、无图表库、无 CSS 框架。图标全部使用 Unicode 几何符号（◈ ⬢ ☰ ⚠ ◔ ☑ ⛔ ▤ ◫ ⇄ ⬓ ▦ ✓ ⇌ ☷ ☗ ⟳ ☖ ▣ ◷）。 |
| 6 | **适合大屏、不迁就手机** | `body { min-width: 1180px }`。这是一个办公后台，不做移动端适配是明确的取舍，而非遗漏。 |

## 二、色彩系统

### 2.1 中性色（8 档灰阶）

| 变量 | 值 | 用途 |
|---|---|---|
| `--c-shell` | `#0f172a` | 侧栏底色（深色侧栏 + 浅色内容区，是 B 端最经得起长时间注视的组合） |
| `--c-shell-2` | `#1e293b` | 侧栏分组底 / 悬停态 |
| `--c-topbar` | `#ffffff` | 顶栏 |
| `--c-bg` | `#f1f5f9` | 内容区底 |
| `--c-bg-2` | `#f8fafc` | 次级底 |
| `--c-card` | `#ffffff` | 卡片 |
| `--c-border` | `#e2e8f0` | 常规描边 |
| `--c-border-strong` | `#cbd5e1` | 强调描边 |

文字四档：`--t-1 #0f172a`（主）/ `--t-2 #334155`（次）/ `--t-3 #64748b`（弱）/ `--t-4 #94a3b8`（占位与禁用）。

### 2.2 品牌主色与角色强调色

```css
--c-primary: #2563eb;   /* 系统级，不随角色变——用于链接、主按钮的语义基线 */

body[data-role="director"] { --c-accent: #4f46e5; }  /* 靛蓝 · 战略 / 全局 */
body[data-role="pm"]       { --c-accent: #0e7490; }  /* 青蓝 · 执行 / 推进 */
```

每个角色配 5 个变量：`--c-accent`（主）/ `-d`（深，悬停）/ `-l`（浅，底）/ `-bd`（描边）/ `-rgb`（用于半透明叠加）。

**这是全站唯一的角色差异点。** 切换角色时 `body[data-role]` 一变，所有引用 `--c-accent` 的地方（选中的侧栏项、主按钮、进度条、首页横幅、图表强调线、Tab 下划线）同步换色，无需任何 JS 逐个改样式。

### 2.3 语义状态色（7 组 × 3 值）

每组含前景 / 背景 / 描边三个值，用于状态标签、行高亮、图表配色的统一。

| 语义 | 前景 | 用于 |
|---|---|---|
| `done` | `#16a34a` 绿 | 已完成 / 已发布 / 已验收 / 正常 |
| `doing` | `#2563eb` 蓝 | 进行中 / 开发中 / 处理中 |
| `plan` | `#7c3aed` 紫 | 规划中 / 待评审 / 未开始 |
| `warn` | `#d97706` 琥珀 | 待处理 / 风险中 / 黄灯 |
| `danger` | `#dc2626` 红 | 延期 / 阻塞 / 红灯 / 已驳回 |
| `idle` | `#64748b` 灰 | 已关闭 / 已取消 / 暂缓 |
| `cyan` | `#0891b2` 青 | 补充维度（避免同图内配色撞车） |

状态到语义的映射统一走 `C.tone(kind, value)`，页面不得自行判断。

### 2.4 优先级色阶

`--p0 #b91c1c` → `--p1 #dc2626` → `--p2 #d97706` → `--p3 #0891b2` → `--p4 #64748b`

从深红到灰，五档单调递减——优先级高低在灰度打印下也能区分。

### 2.5 图表色板（12 色）

`--ch-1` 至 `--ch-12`，蓝 / 绿 / 琥珀 / 紫 / 青 / 红 / 橄榄 / 品红 / 天蓝 / 橙 / 靛 / 翠。**相邻色的色相跨度均 ≥ 40°**，保证同一张图里 6~8 条线也能分辨。`CH.color(i)` 按索引循环取用。

### 2.6 三色灯

风险与项目健康度统一用三色灯（`UI.light`）：红 = `--s-danger`、黄 = `--s-warn`、绿 = `--s-done`。灯是实心圆点 + 同色浅色外圈，直径 8px，在表格行内不撑高行高。

## 三、字体与字号

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC",
             "Hiragino Sans GB", "Microsoft YaHei", "Segoe UI", Roboto, sans-serif;
```

**全部使用系统字体栈**，不加载任何 Web Font——离线可用、零加载闪烁、中英文各自落到系统最优字体。

| 变量 | 值 | 典型用途 |
|---|---|---|
| `--f-xs` | 11px | 表格内的次级说明、图表轴标签 |
| `--f-sm` | 12px | 卡片副标题、标签、meta 行 |
| `--f-base` | **13px** | **全站基准**：正文、表格、表单 |
| `--f-md` | 14px | 卡片标题 |
| `--f-lg` | 16px | 页面主标题 |
| `--f-xl` | 19px | 抽屉标题 |
| `--f-2xl` | 24px | 统计卡数值 |
| `--f-3xl` | 30px | 首页横幅统计 |
| `--f-4xl` | 38px | 指标卡主数值 |

**数字一律用等宽变体**：

```css
.num, .metric-val, .tbl td.num { font-variant-numeric: tabular-nums; }
```

表格里的数字列不会因为字宽不同而参差——这是 B 端表格可读性的关键细节。

## 四、间距与圆角

**8px 基准的间距阶梯**：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40（`--sp-1` ~ `--sp-10`）。

**圆角克制**：

| 变量 | 值 | 用途 |
|---|---|---|
| `--radius-sm` | 4px | 标签、小按钮 |
| `--radius` | 6px | 卡片、输入框、按钮（**主力**） |
| `--radius-lg` | 10px | 抽屉、模态 |
| `--radius-full` | 999px | 头像、三色灯、chips |

没有 16px 以上的大圆角——那是 C 端产品的语言。

**阴影四档且都极浅**：

```css
--shadow-sm: 0 1px 2px  rgba(15,23,42,.06);   /* 卡片默认 */
--shadow:    0 2px 8px  rgba(15,23,42,.08);   /* 卡片悬停 */
--shadow-md: 0 4px 16px rgba(15,23,42,.10);   /* 弹出菜单 */
--shadow-lg: 0 12px 40px rgba(15,23,42,.18);  /* 抽屉、模态 */
```

**不堆叠阴影**：一个元素最多一层。层级关系主要靠描边和底色区分，阴影只用于确实浮起的元素。

## 五、布局骨架

```
--topbar-h:       56px      顶栏固定高度
--sidebar-w:     214px      侧栏展开宽度
--sidebar-w-mini: 56px      侧栏折叠宽度（只留图标）
--crumb-h:        40px      面包屑条高度
```

```
┌────────────────────────────────────────────────┐ 56px 顶栏（固定）
├──────┬─────────────────────────────────────────┤
│      │ 面包屑 40px                              │
│ 214  ├─────────────────────────────────────────┤
│  px  │                                         │
│ 侧栏 │ 内容区（唯一滚动容器）                    │
│(固定)│ 宽度自适应铺满，左右 padding 24px         │
│      │                                         │
└──────┴─────────────────────────────────────────┘
```

`.app { height:100vh; overflow:hidden }`，逐层 `overflow:hidden` 直到 `.content` —— **页面本身不滚动，只有内容区滚动**。顶栏与侧栏永远在位，不会滚出视野。

**栅格**：`.grid` + `.g2` / `.g3` / `.g4` / `.g5` / `.g6`（等分），以及 `.g-2-1` / `.g-1-2` / `.g-3-2` / `.g-1-1-2`（非等分），卡片可加 `.span2` 占两列。

**响应式断点**：面向大屏办公，`layout.css` 只写了两条 `@media` 规则，内容区不设 `max-width`。

| 宽度 | 行为 |
|---|---|
| > 1500px | 全部栅格按声明列数展开，侧栏 214px |
| ≤ 1500px | `.g5` / `.g6` 各降为 3 列（笔记本 1366 宽度下避免指标卡被挤扁） |
| ≤ 1320px | 侧栏收窄为 190px；`.g4` 降为 2 列；顶栏搜索框 `min-width` 收到 160px |
| < 1180px | 出现横向滚动条（`tokens.css:101` `body{min-width:1180px}`），不做进一步适配 |

> 侧栏的 56px 图标态（`.app.mini`）是**手动折叠**，由顶栏 `btnMini` 触发并持久化于 `pmw.mini`，**不随视口自动切换**。

**z-index 分层**（集中定义，避免各处硬编码打架）：

```
--z-pop:    500   弹出菜单
--z-drawer: 600   抽屉
--z-modal:  700   模态
--z-toast:  800   toast
```

## 六、核心组件规范

### 6.1 卡片 `UI.card`

```
┌────────────────────────────────────────────┐
│ ◈ 卡片标题            [右上角 extra 动作] │  ← 40px 标题栏，底部 1px 描边
│   副标题（12px 弱色）                      │
├────────────────────────────────────────────┤
│ 卡片主体（padding 16px；flush 时为 0）      │
└────────────────────────────────────────────┘
```

- 标题带一个 Unicode 图标，与侧栏模块图标同源
- `extra` 通常是 `btn-text` 形态的"→ 去某页"跳转
- `flush: true` 用于内容本身自带内边距的场景（列表、表格）

### 6.2 指标卡 `UI.metric`

```
┌──────────────────┐
│ ⚠ 核心预警        │  ← 12px 弱色标签
│ 5 项              │  ← 38px 等宽数字 + 12px 单位
│ 2 项已升级        │  ← 11px 副文案
└──────────────────┘
```

左侧 3px 竖色条表达语气（done/doing/warn/danger/idle）。整卡可点，跳转到对应模块。

### 6.3 状态标签 `UI.tag` / `UI.st`

浅底 + 同色文字 + 同色描边的三件套，圆角 4px、字号 11px、内边距 2px/6px。**不使用实心色块**——满屏实心标签会让表格变成调色盘。

### 6.4 数据表格 `.tbl`

| 项 | 规格 |
|---|---|
| 表头 | `--c-head #f8fafc` 底、12px、600 字重、sticky |
| 行高 | 40px |
| 斑马纹 | 无（靠 1px 分隔线，斑马纹在宽表里反而干扰） |
| 悬停 | 整行 `--c-bg-2` |
| 危险行 | `.row-danger` 左侧 2px 红条 + 极浅红底 |
| 数字列 | 右对齐 + 等宽数字 |
| 排序 | 表头可点，箭头指示，第二次点反序 |
| 分页 | 右下角，页码 + 上下页，默认 `pageSize: 15` 行（`pageSize: 0` 关闭分页） |
| 勾选 | 表头全选框；选中后底部浮出批量条 |

### 6.5 按钮

| 类名 | 形态 | 用途 |
|---|---|---|
| `.btn-primary` | 实心 `--c-accent` | 每页最多一个主动作 |
| `.btn` | 白底 + 描边 | 次要动作 |
| `.btn-text` | 无底无边，`--c-accent` 文字 | 卡片右上角跳转 |
| `.btn-sm` | 高 26px | 表格行内操作 |
| `[disabled]` | 灰化 + `cursor: not-allowed` + tooltip | 无权限时 |

**同一区域内主按钮不超过一个**——这是避免 B 端界面"按钮海"的最简单规则。

### 6.6 抽屉与模态

- **抽屉**（`UI.drawer`）：右侧滑入，默认 480px，`wide` 720px，`narrow` 380px。用于**详情查看**。
- **模态**（`UI.modal`）：居中，用于**必须做决定**的场景（确认删除、批量操作确认）。

选择规则：**看 → 抽屉；决定 → 模态**。抽屉不打断上下文（列表还在左边），模态强制聚焦。

### 6.7 反馈

- `UI.toast`：右上角，四态（ok / warn / err / info），默认 2200ms 后淡出（220ms 过渡），不阻断操作
- `UI.empty`：图标 + 说明文案 + 可选动作（如"清空筛选"）——空态永远给出下一步
- `UI.notice`：页面顶部说明条，五种语气（info / warn / danger / done / plain），权限说明条用的就是它

## 七、图表风格

| 项 | 规格 |
|---|---|
| 实现 | **纯 SVG 自绘**，`assets/js/04-charts.js`，11 个方法覆盖 15 种图形（`ringSVG` 进度环已实现未启用，实际呈现 14 种），零依赖 |
| 网格线 | 仅横向，`#e2e8f0` 1px，Y 轴刻度 4~5 档 |
| 坐标轴 | 无轴线，只有刻度文字（11px `--t-3`） |
| 数据标签 | 默认不显示，靠 tooltip；仅横向排行条（`CH.bars`）内嵌文案 |
| tooltip | 全站共用一个 `#chartTip`，跟随鼠标，深色底白字，行式 KV |
| 图例 | 可点击开关系列，关闭的系列变灰但保留占位 |
| 交互 | 所有图表支持 `onClick`；**默认行为是回填当前页筛选条件而非跳页**，保持上下文 |
| 重绘 | `CH.redrawAll` 监听 `resize`，160ms 防抖 |

**为什么自绘而不用图表库**：整套系统要能双击 `index.html` 离线打开。引入任何 CDN 图表库都会破坏这个前提；把库文件下载到本地又会让体积从几百 KB 涨到几 MB。自绘的代价是 15 种图表约 1200 行代码，收益是零依赖、零加载、完全可控的配色与交互。

## 八、打印

`print.css` 做 A4 横向适配：

- 隐藏顶栏、侧栏、筛选条、分页器、所有按钮
- 内容区展开为全宽，卡片去阴影留描边
- 表格 `thead` 设 `display: table-header-group`，跨页时表头自动重复
- 图表 SVG 原样打印（矢量，不糊）
- 页脚打印生成时间与数据口径

PDF 导出即走浏览器打印（`⌘P` → 存储为 PDF），不内嵌 PDF 库。

## 九、Word 导出的样式约定

`U.exportWord` 生成 HTML 伪装的 `.doc`，Word / WPS 可正常打开：

- 内联样式（Word 对外部样式表支持差）
- 表格统一 1px 灰边框 + 浅灰表头
- 标题层级用 `h2` / `h3`，正文 11pt 宋体 / 英文 Calibri
- 文档头部固定一行 meta：`导出角色 | 数据口径 | 生成时间 | {自定义补充}`

## 十、可访问性与细节

- 所有可点区域最小热区 28×28px
- 焦点态保留（`:focus-visible` 显示 2px accent 描边），键盘可完整操作表格与表单
- 全局快捷键：`⌘K` / `Ctrl+K` 唤起搜索，`ESC` 关闭抽屉与模态
- 滚动条统一定制为 9px 灰色圆角，轨道透明
- 长文本一律 `U.ellip(text, n)` 截断并保留完整值在 `title` 属性中
- 日期一律 `YYYY-MM-DD`，表格内可缩为 `MM-DD`；相对时间（"3 天后到期"）只用于徽标，不用于表格列

## 十一、反面清单（明确不做的事）

| 不做 | 原因 |
|---|---|
| 渐变背景（首页横幅除外） | B 端界面的渐变会干扰数据读取；横幅是唯一例外，用于强化角色识别 |
| 图标字体 / SVG 图标库 | 破坏离线可用；Unicode 几何符号足够表达模块语义 |
| 骨架屏 | 纯静态无网络请求，数据同步就绪，骨架屏只会制造虚假的等待感 |
| 数字滚动动画 | 用户要读数，不要看表演 |
| 深色模式 | 双主题会让"角色换色"这一核心机制的表达空间被挤占；企业办公场景日间为主 |
| 移动端适配 | 甘特、热力矩阵、24 列工时表在手机上无法有效呈现，勉强适配不如明确不做 |
| 卡片阴影堆叠 / 大圆角 | C 端语言，会削弱专业感 |
