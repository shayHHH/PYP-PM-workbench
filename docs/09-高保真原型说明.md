# 09 · 高保真原型说明

> 对应输出要求第 ⑨ 项。本文说明这套东西「是什么、怎么打开、数据从哪来、按什么动线上手、哪些是真的哪些还没接」。

---

## 一、这不是静态图，也不是演示 demo，是一个能直接用的工具

| 维度 | 常见的"高保真原型" | 本工程 |
|---|---|---|
| 载体 | Figma / Axure 画板 | 真实浏览器中运行的 HTML/JS/CSS |
| 数据 | 每个画板手工填假数字 | **开箱是空库，一条假数据都没有；里面的每条记录都是你自己录的** |
| 持久化 | 无 | 写 `localStorage['pmw.db']`，刷新、关机、下次打开都还在 |
| 交互 | 热区跳转 | 真实路由、真实排序分页、真实拖拽、真实表单校验 |
| 图表 | 截图或占位图 | 15 种纯 SVG 自绘图表，带 tooltip / 图例开关 / 点击下钻 |
| 角色切换 | 两套独立画板 | 同一份数据 + 同一套组件，按 `body[data-role]` 与权限矩阵实时切换 |
| 导出 | 无 | CSV / Word（`.doc`）/ JSON / 浏览器打印真实可用 |

**为什么不带示例数据？** 带了就必然要编公司名、编人名、编需求标题。那些编出来的东西一旦混进你的真实记录里就分不清了，而且会让你误以为某个模块"已经有内容"。所以这里的选择是：**宁可开箱是白纸，也不塞一条假的。** 白纸怎么下笔，由「上手与数据」模块负责教（见下文第三节）。

也就是说：**它已经是产品本身的前端形态，只差把 `S.DB` 从本地库换成后端接口。**

## 二、怎么打开

### 方式 A：双击（推荐，日常就这么用）

直接双击项目根目录的 `index.html`。

- 无需 Node、无需 npm、无需构建、无需联网
- 无任何 CDN 依赖，全部资源为本地相对路径
- 断网、内网、U 盘拷贝均可运行

建议把它拖进书签栏或做个桌面快捷方式，当成一个本地应用来开。

### 方式 B：本地静态服务（开发调试用）

```bash
cd "产品总监工作台1"
node /tmp/wb-serve.js          # 或任意静态服务器
```

浏览器打开 `http://localhost:8777/`。

> ⚠️ **两种方式的数据不互通。** 浏览器把 `localStorage` 按「源」隔离，`file://` 和 `http://localhost:8777` 是两个不同的源，各有一份独立的 `pmw.db`。**选定一种打开方式后就一直用它**；确实要换，走「上手与数据 → 数据管理」导出 JSON 再导入。

### 环境要求

- 现代浏览器（Chrome / Edge / Safari / Firefox 近两年版本）
- **最小可用宽度 1180px**（`tokens.css` 中 `body{min-width:1180px}`）。这是刻意的：本系统面向大屏办公，不做移动端适配（见 `08-UI风格规范.md` 第十一节）
- 推荐 1440×900 及以上，1920×1080 体验最佳

## 三、数据从哪来：你自己录

### 3.1 开箱状态

第一次打开时 `localStorage` 里没有 `pmw.db`，`DATA.blank()` 造一个空库：

- `COLLS` 定义的 28 个业务集合先全部置为空数组
- `org = { name:'我的组织', bu:'' }`、`me = { name:'' }` —— 两个占位值，等你去填
- `members` 里**只有一条 `M01`「我」**。这条不是数据，是脚手架：所有「负责人 / 处理人 / 审批人」下拉框都取自成员表，成员表全空的话一条业务记录都建不出来。你在「组织与我」里填了真名，这条会同步改名。

首次打开会弹一次欢迎窗（`DATA.seen()` 记住，只弹一次），点「开始上手」直接进 `#/guide/start`。

### 3.2 上手清单（`G.steps()`，共定义 9 条，按角色过滤后总监 8 条 / PM 6 条）

清单的打钩**不需要你手动点**，全部由真实数据量推导。做完一步自动变绿，全部做完卡片从首页消失。

| # | 步骤 | 完成判据 | 角色 |
|---|---|---|---|
| 1 | 填组织抬头和你的名字 | `org.name !== '我的组织'` 且 `me.name` 非空 | 两者 |
| 2 | 建第一条产品线 | `lines.length > 0` | 总监 |
| 3 | 建第一个项目 | `projects.length > 0` | 两者 |
| 4 | 把常打交道的人录进成员表 | `members.length > 1`（除你自己外还有人） | 总监 |
| 5 | 录第一条需求 | `requirements.length > 0` | 两者 |
| 6 | 排第一个版本 | `releases.length > 0` | 总监 |
| 7 | 拆第一批任务 | `tasks.length > 0` | PM |
| 8 | 登记一条风险或记一次会议 | `risks.length > 0 \|\| meetings.length > 0` | 两者 |
| 9 | 导出一份备份 | `setupFlags().backup` | 两者 |

**过滤后你实际看到的**：总监 8 条（1–6、8、9），项目经理 6 条（1、3、5、7、8、9）。进度百分比的分母是过滤后的条数，所以 PM 做完 6 条就是 100%。

> 顺序是有依赖的：**产品线 → 项目 → 成员 → 需求 → 版本 / 任务**。跳着做也不会报错，但需求的「所属产品线」下拉会是空的。
>
> 项目经理清单里没有「建产品线」，是因为产品线归总监管（`roadmap` 对 PM 为 `none`）。如果只有你一个人用，先切到总监角色把产品线建好，再切回项目经理。

### 3.3 每个模块的空态都在教你怎么用

`G.TIP` 为全部 21 个模块各写了一段，`G.emptyFor(mod)` 渲染成教学式空态，包含四块内容：

- **这是什么** —— 一句话说清这个模块解决什么问题
- **什么时候用** —— 什么场景下你会想打开它
- **第一步做什么** —— 具体到「填哪几个字段、为什么这几个字段重要」
- **一个主行动按钮** —— 直接拉起对应的新建表单

`G.countOf(mod)` 会区分两种空：**整个模块一条数据都没有**（教你怎么开始）vs **只是当前口径下没数据**（提示你换个产品线 / 项目看看）。这两种情况该说的话完全不同。

### 3.4 数据存在哪、什么时候会丢

| 问题 | 答案 |
|---|---|
| 存在哪 | 这台电脑、这个浏览器的 `localStorage`，键名 `pmw.db` |
| 什么时候写 | 每一次 `S.add / S.update / S.remove` 之后立刻整库写入，没有「保存」按钮 |
| 会上传吗 | 不会。全程无任何网络请求，断网可用 |
| 什么情况会丢 | 清除浏览数据 / 卸载浏览器 / 换电脑 / 换浏览器 / 换打开方式（`file://` ↔ `http://`）|
| 怎么保险 | 「上手与数据 → 数据管理 → 导出 JSON」。这是唯一的备份手段，别偷懒 |

「今天」由 `S.TODAY` 统一提供，每次打开页面按真实系统时间重算。全站 76 处逾期 / 临期 / 环比计算都走它，没有任何写死的基准日。

## 四、双角色使用动线

### 4.1 第一次上手（大约 20 分钟，做完就有真数据可看）

**第 1 步 · 认顶栏**

打开 `index.html`。顶栏从左到右：品牌 → 组织抬头 → 产品线与项目选择器 → 状态标签 → 全局搜索 → 时钟 → **角色切换开关** → 提醒铃 → 新建 → 用户信息。

要记住的只有一件事：**右上角那个开关决定了你看到的是哪一套视图，但底层数据只有一份。**

**第 2 步 · 填「组织与我」**

`#/guide/start` → 第一条 → 「去填写」。填公司名、事业部（可留空）、你的名字。填完顶栏立刻变。

**第 3 步 · 搭骨架：产品线 → 项目 → 成员**

按清单第 2/3/4 条依次做。建项目时**记得勾上「创建标准阶段」**，否则甘特图、进度跟踪、里程碑三个页面都没有底座。

**第 4 步 · 灌第一批业务数据**

录 3～5 条需求（业务价值和预估人日一定要填，它们决定需求在价值-成本四象限里的位置）→ 排 1 个版本 → 把需求挂到版本上 → 拆一批任务派到人。

**第 5 步 · 立刻导出一份备份**

「上手与数据 → 数据管理 → 导出 JSON」。

### 4.2 数据攒起来之后，两个角色分别看什么

**总监视角**

- 首页：6 张指标卡 → 产品线进展对比（**点柱子会切换全局产品线口径，整页数据跟着收敛**）→ 需求流转漏斗 → 经营指标趋势 → 本周关注 → 风险三色灯 → 决策记录时间轴
- 产品规划 → 路线图：泳道视图，一行一条产品线，一列一个季度
- 数据分析：先用「＋新建 → 指标数据」把 ARR / 活跃用户 / 续约率等按周录进去，攒够两周才有环比和趋势
- 经营复盘：目标完成率 → 问题清单 → 归因 → 改进动作到人，然后导出 Word

**PM 视角**

- 首页：6 张指标卡（里程碑达成率 / 延期任务 / 未关闭风险 / 阻塞事项超阈值会自己变红）→ 项目阶段进度（进度条 + 甘特）→ 本周交付 → 我的待办 → 任务分布 → 阻塞与延期 → 会议 Action
- **可以直接在首页勾掉一条待办** —— 全站唯一在首页做写操作的地方
- 任务管理：列表 / 看板双视图，拖卡片换列即改状态并落库
- 进度跟踪：甘特图 + 延期分析

### 4.3 切角色时当场发生的五件事

点右上角「项目经理」：

1. 全站强调色由靛蓝 `#4f46e5` 变为青 `#0e7490`
2. 侧栏模块整组替换：产品规划 / 用户反馈 / 团队管理 / 经营复盘 消失，项目计划 / 任务管理 / 进度跟踪 / 资源协调 / 需求变更 / 交付管理 / 周报月报 出现
3. 首页整页换版，指标卡从"体检式"变成"报警式"
4. 顶栏数据口径由"产品线"收敛为"当前项目"
5. 用户信息里的职位由「产品总监」变为「项目经理」——**姓名不变，因为那是你自己**

### 4.4 权限边界

- 侧栏 → 需求管理：注意页面顶部多了一条黄色权限说明条 ——「项目经理可查看与推进需求状态，但调整优先级、关闭 / 驳回需求、指派目标版本均需通过「需求变更」走审批。」
  - 随手打开任意一条需求的**编辑抽屉**：「优先级」不是下拉框，而是一枚只读标签 + 「如需调整请提交『需求变更』走审批」；状态下拉里也找不到「已关闭 / 已驳回」
  - 勾选两三条需求：底部批量动作只剩「批量流转状态 / 批量提交变更申请 / 批量导出」，没有总监才有的「批量调整优先级 / 批量指派版本」
- 侧栏 → 版本管理 → 版本计划：打开编辑抽屉，开发启动 / 需求冻结 / 提测 / 计划上线四个日期均为只读并标注「总监排期」，批量动作里没有「批量顺延上线日」
- 侧栏 → 数据分析：说明条变为「漏斗与留存已收敛到当前项目关联的版本与需求；核心指标按当前项目所属产品线口径展示，ARR / MAU / 续约率等经营指标仅产品总监可见。」；核心指标看板上只剩 NPS / 工单量 / SLA 三张卡，且顶部没有产品线选择器。**「＋新建 → 指标数据」在 PM 视角下也只列出这三个槽位**（`99-app.js` 里的 `PM_ONLY`），录不了 ARR / MAU / 续约率
- **在地址栏手动输入 `#/roadmap/lines`** —— 落到"无权限"说明页，不是白屏、不是报错

### 4.5 三个容易被忽略的地方

| 主题 | 路径 | 看点 |
|---|---|---|
| 全局搜索 | 按 `⌘K` / `Ctrl+K`，输入任意关键词 | 跨 6 类实体的分组结果，回车直达详情抽屉 |
| 保存视图 | 需求管理 → 需求池 → 调筛选 → 保存视图 → 命名 → 重置 → 一键切回 | 视图**按角色分别存储** |
| 留痕闭环 | 任意页做一次新建 → 工作留痕 → 时间轴顶部就是刚才那条 | 每次增删改自动生成留痕，不用手写工作日志 |

## 五、能力边界

诚实说明哪些已经能真用、哪些还没接，避免你在某个地方白等。

### 5.1 完全可用（就是最终产品的样子）

- 全部 59 个页面的信息架构、字段、列、筛选项、按钮
- 路由、面包屑、详情页返回栈
- 排序 / 分页 / 勾选 / 批量操作 / 空态 / 校验 / toast / 抽屉 / 模态
- 图表的类型、坐标轴、图例、tooltip、点击行为
- 权限矩阵的四态行为（侧栏可见性、按钮灰化、说明条、无权限页）
- CSV / Word / JSON 导出，浏览器打印
- **数据持久化**：`localStorage['pmw.db']`，每次增删改立刻落盘
- 偏好记忆（角色、项目、产品线、侧栏折叠、筛选、保存视图）
- **今天** = 真实系统时间，逾期 / 临期 / 环比全部按真实日期算

### 5.2 还没接（单机版的固有边界）

| 项 | 现状 | 要多人协作时 |
|---|---|---|
| 数据源 | 浏览器 `localStorage`，单机单浏览器 | 换后端 API；`03-store.js` 的取数方法签名可保持不变 |
| 持久化 | 同步写本地 | 写后端；`S.add/update/remove` 改为异步 |
| 多人协同 | **没有**。这是一个人用的工具，靠导出 JSON 传递 | 接后端后天然支持 |
| 登录与身份 | 你的名字存在本地库，角色由右上角开关切换 | 由登录态与组织架构决定；角色开关退化为"我有多个角色时的视角切换" |
| 审批流 | 状态字段直接改写 | 接工作流引擎 |
| 附件与 PRD 文档 | 只记文件名与元信息，不存文件本身 | 接对象存储 |
| 通知提醒 | 由数据条件实时算出，只在页面内展示 | 接消息中心 / 邮件 / IM |
| Word 导出 | HTML 伪装 `.doc`，Word 可正常打开 | 可保留（成本极低），或换服务端渲染 `.docx` / PDF |

### 5.3 明确不做的（不是遗漏，是取舍）

- 移动端 / 响应式到手机宽度 —— 面向大屏办公
- 深色模式 —— 企业后台使用场景以白天办公为主，双主题会使角色 accent 的语义被稀释
- 骨架屏与加载动画 —— 无网络请求，加了反而是假的
- 数字滚动、渐变、图标字体 —— 见 `08-UI风格规范.md` 反面清单
- 国际化 —— 面向内部单语种团队

## 六、常见问题

**Q：为什么一条示例数据都没有？我想先看看效果。**
A：这是刻意的。带示例数据就必须编公司名、编人名、编需求标题，那些东西一旦和你的真实记录混在一起就分不清了，而且会让你误以为某个模块"已经有内容"。想看效果的最快路径是照着 §4.1 花二十分钟录一遍真数据 —— 反正这些数据你本来就要录。

**Q：我的数据会不会传到哪里去？**
A：不会。全程零网络请求，断网可用。数据只在这台电脑这个浏览器的 `localStorage` 里。代价是**没有任何云端备份**，所以「导出 JSON」不是可选项。

**Q：换电脑怎么办？**
A：旧机器「数据管理 → 导出 JSON」，新机器「导入 JSON」。整库覆盖式导入。

**Q：为什么总监完全看不到"任务管理"，而不是只读？**
A：见 `07-角色权限与展示差异.md` 第三节。总监需要的执行面信息已经通过仪表盘 / 风险预警 / 项目协同 / 数据分析四个公共模块以聚合口径呈现；给一个"能看不能改的任务列表"只会稀释决策注意力。真正的跨角色只读只有 `analytics` 对 PM 一处。

**Q：切角色会不会改数据？**
A：不会。切角色只改变 ①视图编排 ②默认排序与筛选 ③可见模块 ④数据口径（产品线 vs 单项目）。`S.DB` 一个字节都不变。可以自己验证：总监下新建一条需求 → 切 PM → 需求池里能找到同一条。唯一按角色分桶的是**待办**（`todos` 带 `role` 字段），因为两个视角关心的待办本来就不是一回事。

**Q：图表为什么不用 ECharts？**
A：见 `08-UI风格规范.md` 第九节。核心原因是零依赖 / 可离线 / 可完全控制视觉语言，且本系统需要的 15 种图表都在自绘可控范围内。

**Q：这份代码能直接给前端开发用吗？**
A：可以，且建议直接用。分层结构、组件契约、如何新增模块见 `10-前端组件拆分方案.md`。

## 七、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面左右出现横向滚动条 | 窗口宽度 < 1180px | 放大窗口，或接受横向滚动 |
| 双击打开后某些字体渲染不同 | 使用系统字体栈，不同 OS 略有差异 | 属预期，非缺陷 |
| **打开后数据全没了** | 换了打开方式（`file://` ↔ `http://localhost`），或清过浏览器数据 | 换回原来的打开方式；若已清除，只能从导出的 JSON 恢复 |
| 想清空重来 | — | 「上手与数据 → 数据管理 → 清空我的全部数据」（**两道确认**，建议先导出备份） |
| 导出的 `.doc` 双击提示格式警告 | 本质是 HTML 伪装 | 选择"仍然打开"即可，内容与排版正常 |
| 控制台有 404 | 缺文件或路径大小写不符 | 核对 `index.html` 中 31 个 `<script>` 与 4 个 `<link>` 路径 |
