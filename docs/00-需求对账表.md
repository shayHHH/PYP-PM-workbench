## 九、已知取舍与说明

以下为**有意为之的实现取舍**，不属于遗漏：

1. **开箱是空库，不带任何示例数据。** `02b-data.js` 的 `blank()` 造出 `COLLS` 定义的 28 个业务集合、全是空数组，随后只往 `members` 里放「你自己」一条脚手架记录。你在任何页面上看到的每一条业务记录，都是你自己录进去的。
   - 这是按你「**这个是我真实要用的工具，不要乱塞数据**」「**不要示例数据，我要的是一个可以直接用的工具**」两条要求做的调整。早期版本确实有一份确定性种子数据（`02-seed.js`），现已**停止引用**，该文件不再出现在 `index.html` 的 31 个 `<script>` 里。
   - 代价是第一次打开时 20 个模块全是空的，所以补了 `guide` 模块与教学式空态兜底（见 5.4）。
2. **时间基准跟随系统时间。** `S.TODAY` / `S.quarters` 每次加载页面时按 `new Date()` 重算，不再固定在某一天。
3. **数据真持久化，写在这台电脑这个浏览器上。** 每一次新建 / 编辑 / 删除都立刻经 `S.persist()` → `DATA.save()` 整库写入 `localStorage['pmw.db']`，刷新不丢，不需要点保存。
   - 没有服务器、不联网，因此**换浏览器、换电脑、清理浏览器数据都会看不到**。「数据管理」页提供导出 / 导入 JSON 用于备份与换机。
   - 顶栏用户菜单里的「**重置界面偏好（不动数据）**」（`06-shell.js:358`）只清角色、产品线 / 项目选择、保存的视图与排序偏好这 6 个键，**不碰业务数据**。要清业务数据得去「数据管理」页，那里有两道确认。
4. **PDF 导出走浏览器打印**（`print.css` 已做 A4 横向适配），未内嵌 PDF 生成库，以保持零依赖。
5. **Word 导出为 HTML 伪装 `.doc`**，Word / WPS 可正常打开并保留表格样式；不是真正的 OOXML。
6. **两组增强模块互不可见（`none`），不是只读**：总监侧栏不渲染 7 个 PM 执行模块（项目计划 / 任务管理 / 进度跟踪 / 资源协调 / 需求变更 / 交付管理 / 周报月报），PM 侧栏不渲染 4 个总监战略模块（产品规划 / 用户反馈 / 团队管理 / 经营复盘）。直接输入 hash 路由会落到"无权限"说明页而非白屏。
   - 设计理由：总监关心的执行面结果已通过"仪表盘 / 风险预警 / 项目协同 / 数据分析"四个公共模块以聚合口径呈现，无需下沉到任务条目级；把执行工具塞进总监视角只会稀释其决策注意力。
   - 真正的**跨角色只读**只有一处：`analytics` 对 PM 为 `scoped`，PM 可看数据分析但不能改口径配置。另有 `requirements` / `releases` 对 PM 为 `limited`（可编辑本项目范围内的字段，不可调整业务价值与产品线归属）。
7. **周报月报为实时汇总而非手工录入**：正文由任务、里程碑、风险、变更、交付、跨部门协同六类数据自动生成，导出 Word 后可人工补充。空库时汇总出来就是空的，得先有任务和里程碑。
8. **数据分析的 6 个指标是固定槽位，不能任意新增。** `13-analytics.js` 的看板与达标判断围绕 `arr / mau / renew / nps / ticket / sla` 六个 key 组织，所以「录入指标数据」（顶栏 ＋ 新建）是往这六个槽位里按周填数，而不是自由建指标。
   - 槽位只预置**建议的名称 / 单位 / 数值格式**（`C.METRIC_SLOTS`），这些录入时可以全部改掉；**目标值和实际值一个都没预设**，必须你自己填。
   - 权限对齐 `PERM_NOTE['analytics.pm']`：ARR / MAU / 续约率属经营指标，仅总监可录；PM 只能录 NPS / 工单量 / 可用性三个交付质量指标。
