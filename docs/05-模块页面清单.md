# 05 · 模块页面清单

## 10. 上手与数据 `guide` ◎

| 子页 | 路由 | 定位 | 主要构成 |
|---|---|---|---|
| 上手引导 `start` | `#/guide/start` | 不知道下一步做什么时的落脚点 | 数据量条 + 上手清单 `G.setupCard`（总监 8 步 / PM 6 步）+ 「当前角色视角」说明 + 常用操作速查 + 「数据存在哪里」 |
| 功能地图 `map` | `#/guide/map` | 当前角色可见的每个模块各是干什么的 | 按导航分组渲染模块卡，每张写「是什么 / 什么时候用 / 第一步做什么」+ 当前数据量，点卡片直达 |
| 数据管理 `data` | `#/guide/data` | 备份、迁移、清空、组织与我 | 数据存放位置说明 + 组织与我（可改） + 导出 / 导入 JSON + 14 类数据量清单 + 清空 |

这是唯一一个不承载业务实体的模块。它存在的理由只有一个：**开箱是空库，得有人告诉你从哪下笔。**

- **上手清单**（`G.setupCard`）共定义 9 步，按 `roles` 过滤后**总监看到 8 步、PM 看到 6 步**（产品线 / 成员 / 版本三步仅总监，任务一步仅 PM）。打钩状态**由真实数据量推导**，不是手动勾选：如「把常打交道的人录进成员表」在 `cnt.members > 1` 时自动打钩（空库自带「你自己」一条，所以阈值是 1 而不是 0）；「填组织抬头和你的名字」要求 `org.name` 已改过默认值且 `S.me().name` 非空。逐步判据见 `06-页面字段与组件规格.md` §20.1。
- **功能地图**与各模块的**教学式空态**共用同一份文案 `G.TIP`（覆盖全部 21 个模块），靠 `G.emptyFor(mod)` 渲染。所以任何一个空页面上写的都不是「暂无数据」，而是这个模块解决什么问题、你的第一步该做什么。
- **数据管理**里的导入是**整库替换**而非合并；清空走 `DATA.clearReal()` 并二次确认。两者都会 `location.reload()`。

**角色差异**：无权限差异，两角色都是 `full`。功能地图按 `C.navFor(role)` 渲染，所以总监看到 14 个模块卡、PM 看到 17 个。

>
> 若改按"是否含可排序分页主表"这一机械口径统计：**43 个子页含 `UI.table` 主表**，**16 个不含**——`dashboard/main`、`requirements/priority`（四象限矩阵）、`releases/timeline`、`releases/compare`、`collab/board`（看板）、`collab/stream`（动态流）、`trace/timeline`、`todos/notes`（卡片墙）、`roadmap/lines`（卡片墙）、`roadmap/map`（泳道）、`feedback/cluster`（卡片墙）、`tasks/kanban`（看板）、`progress/gantt`、`guide/start`、`guide/map`、`guide/data`。

**图表使用统计**：全站共 **119 处**图表绘制调用（另有 22 处 `CH.tipRow / bindTip / color / redrawAll` 辅助调用），全部来自 `CH` 的 **9 个绘制函数**（`line / bar / bars / donut / funnel / flow / heat / gantt / timeline`）与 **1 个内联 SVG 生成器** `sparkSVG`（迷你走势）。通过参数组合（`opt.area` 面积、`opt.stack` 堆叠、`opt.horizontal` 横向条）覆盖折线 / 面积 / 柱 / 堆叠柱 / 横向排行 / 环形 / 漏斗 / 流转阶梯 / 热力矩阵 / 甘特 / 发布时间线 / 迷你走势等形态，无任何第三方图表库。

按调用次数：`bars` 36、`bar` 27、`donut` 24、`line` 12、`heat` 8、`gantt` 5、`funnel` 2、`flow` 2、`sparkSVG` 2（`UI.metric` 指标卡走势、`analytics/kpi` 表内走势）、`timeline` 1。

> `CH.ringSVG`（进度环）已实现并导出，但当前 59 个子页均未调用——进度展示统一用 `UI.progress` 的条形形态。保留该函数作为备用组件，如需环形进度可直接启用。

**导出覆盖**：59 个子页中，**51 个**提供 Word 导出，**48 个**提供 CSV 导出，**6 个**提供打印（A4 横向）。

- 无 Word 导出的 8 个子页：`dashboard/main`（首页，无导出）、`requirements/priority`（四象限，仅 CSV）、`releases/timeline`（时间线，仅打印）、`tasks/kanban`（看板，导出统一放在列表页）、`resources/load`（负载矩阵，仅 CSV + 打印）、`guide/start`、`guide/map`、`guide/data`（说明页，无业务数据可导）
- 无 CSV 导出的 11 个子页：`dashboard/main`、`releases/timeline`、`releases/compare`、`team/efficiency`、`bizreview/cause`、`tasks/kanban`、`progress/gantt`、`changes/impact`（图表推理页，导出以 Word 报告为主）+ `guide/start`、`guide/map`、`guide/data`

> `guide/data` 提供的**导出 JSON 整库备份**与上面三类导出不是一回事：CSV / Word 导出的是**当前页筛选后的业务视图**，用于对外汇报；JSON 导出的是**整个 `pmw.db`**，用于备份与换机迁移，不可读也不用于汇报。
- 提供打印的 6 个子页：`releases/timeline`、`progress/gantt`、`resources/load`、`changes/impact`、`reports/weekly`、`reports/monthly`（后两者共用 `page()` 渲染，故代码中为 5 处 `U.printPage()` 绑定）
