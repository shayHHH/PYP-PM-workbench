# 10 · 前端组件拆分方案

> 对应输出要求第 ⑩ 项。本文是这套原型的**工程结构说明书**：分层怎么切、每层导出什么、模块页面遵守什么契约、新增一个模块要动哪几处、以后要迁到 Vue/React 该怎么迁。
>
> 文中所有方法名均从源码实读，可直接 grep 验证。

**没有构建、没有模块打包器、没有 CDN。** 每个文件是一个 IIFE，把单一大写命名空间挂到 `window`，靠 `index.html` 里 `<script>` 的书写顺序决定加载序。文件名前缀数字就是加载序，也是依赖序。

## 二、九层依赖

依赖是**严格单向**的，下层永不引用上层：

```
                    ┌──────────────────────────────┐
  21 个模块页面 ────▶│  G (08)  引导层               │
  09 / 10~18 /      └───────┬──────────────────────┘
  20~23 / 30~36     ┌───────▼──────────────────────┐
         ├─────────▶│  P (07)  页面级助手           │
         │          └───────┬──────────────────────┘
         │          ┌───────▼──────────────────────┐
         └─────────▶│  Shell (06) 路由与外壳        │
                    └───────┬──────────────────────┘
              ┌─────────────┼─────────────┐
        ┌─────▼─────┐ ┌─────▼─────┐ ┌────▼──────┐
        │ UI (05)   │ │ CH (04)   │ │ S (03)    │
        │ 组件库    │ │ 图表引擎  │ │ 数据仓库  │
        └─────┬─────┘ └─────┬─────┘ └────┬──────┘
              │             │        ┌───▼────────┐
              │             │        │ DATA (02b) │
              │             │        │ 本地库     │
              │             │        └───┬────────┘
              └─────────────┴────────────┤
                        ┌────────────────▼─────┐
                        │  C (01)   配置        │
                        └────────────┬─────────┘
                        ┌────────────▼─────────┐
                        │  U (00)   工具        │
                        └──────────────────────┘
```

一句话读懂每层职责：

| 层 | 命名空间 | 是否持有状态 | 一句话 |
|---|---|---|---|
| 00-util | `U` | 否 | 纯函数：日期、数字、集合、导出、localStorage |
| 01-config | `C` | 否（常量） | 系统里所有"规则"的唯一出处：角色、导航、字典、权限、编排、指标槽位 |
| 02b-data | `DATA` | 是（持有整库） | **唯一和 `localStorage` 打交道的地方**。开箱 `blank()` 造一个空库——`COLLS` 的 28 个业务集合全置空数组，随后只往 `members` 里放「你自己」一条；负责 `save / load / export / import / clearReal` |
| 03-store | `S` | **是** | 唯一状态持有者：当前角色、产品线、项目 + 全部取数与派生统计；每次 CRUD 后调 `DATA.save()` 落盘 |
| 04-charts | `CH` | 只持有图表注册表 | 15 种纯 SVG 图表 + tooltip + 重绘 |
| 05-ui | `UI` | 否 | 无业务语义的通用组件 |
| 06-shell | `Shell` | 是（路由态） | hash 路由、侧栏、顶栏、搜索、角色切换、页面注册表 |
| 07-page | `P` | 否 | 21 个模块共用的页面级套路（权限提示、筛选条、导出、Word） |
| 08-guide | `G` | 否 | 首次欢迎、上手清单（定义 9 步，按角色过滤后总监 8 / PM 6）、21 个模块的教学式空态文案 `G.TIP` |
| 09 / 10~36 | 无（自注册） | 否 | 21 个模块页（20 业务 + 1 上手与数据），每个只做"编排" |
| 99-app | 无 | 否 | 注册 15 个快捷新建 + `Shell.init()` |

> **`02-seed.js` 已不在 `index.html` 的引用列表里。** 早期版本用它生成一整套演示数据；现在这是一个**真实使用的工具，开箱即空库**，不预置任何业务数据，该文件因此彻底停用。

## 三、各层导出清单（实读源码）

### 3.1 `U`（00-util.js，约 320 行）

```
DOM       esc, $, $$, el, on
日期      pad, toDate, fmtDate, fmtMD, today, dayDiff, addDay, daysLeft,
          relTime, dueText, weekOf, monthOf, quarterOf, weekRange, inRange, WD
数字      num, fmtNum, kmb, pct, pctStr, clamp, sum, avg, max, min, delta
集合      by, group, countBy, uniq, sortBy, orderBy, take
文本      match, matchAny, hl, ellip, initials, avaCls
存储      uid, save, load, drop, dropAll
导出      download, toCSV, exportCSV, exportWord, exportJSON, printPage
杂项      debounce, copy, clone, rng, randPick
```

> `U.hl()` 是搜索结果高亮，`U.avaCls()` 按姓名散列出头像色，`U.rng(seed)` 是种子伪随机 —— 这三个是"看似业务、实为工具"的边界案例，放在 U 层是因为它们不读任何业务状态。

### 3.2 `C`（01-config.js，约 440 行）

```
数据    ORG, ROLES, NAV, MOD, DICT, TONE, PERM, PERM_NOTE, CREATE, VIEW, HOME, METRIC_SLOTS
函数    navFor, canSee, permOf, canEdit, tone, isTerminal, isBad, createFor, viewOf, slotOf
```

**这是全系统最重要的一个文件。** 角色定义、21 个模块与 59 个子页的导航树、所有状态字典、权限矩阵、每个角色的默认视图、两套首页的编排顺序，全都在这里。改一处配置，21 个模块页面同步生效。

`METRIC_SLOTS` / `slotOf` 是后加的一组：数据分析模块围绕 6 个固定 key（`arr / mau / renew / nps / ticket / sla`）组织看板与达标判断，所以指标不是任意新建的，而是往这 6 个槽位里填数。槽位只给出**建议的名称 / 单位 / 格式**，目标值与实际值全部由使用者自己录——这里不预设任何业务数字。

两套判定必须分清：

- `C.canSee(mod, role)` —— 基于 `NAV` 分组的 `roles` 字段，决定**侧栏渲不渲染这个模块**
- `C.permOf(mod, role)` / `C.canEdit(mod, role)` —— 基于 `PERM` 矩阵，决定**按钮能不能点**

二者互相独立。详见 `07-角色权限与展示差异.md`。

### 3.3 `S`（03-store.js，约 435 行）

```
状态     DB, state, onChange, emit
角色     role, roleObj, isDirector, isPM, setRole, setLine, setProject
按 ID    lineBy, projBy, relBy, reqBy, taskBy, riskBy, meetBy, memBy
当前     curLine, curProject, projectsInScope, linesInScope, scopeFilter
取数     reqs, rels, tasks, risks, issues, meetings, actions, feedbacks,
         changes, deliverables, phases, milestones, traces, cross,
         roadmap, okrs, reviews, reports, todos, members
派生     metric, progressOf, projectStat, lineStat, reqFlow, releaseOnTime,
         weekFocus, weekDelivery, homeMetrics, scopeStatus
搜索     search
写入     add, update, remove
偏好     pref, setPref, savedViews, saveView, dropView
```

三条铁律：

1. **模块页面禁止直接读 `S.DB` 或 `DATA`**，一律走 `S.xxx()`。所有取数方法内部都过了 `scopeFilter`，自动按当前角色口径（总监=产品线 / PM=单项目）收敛。
2. **`S` 是唯一的状态持有者**。`Shell` 只持有路由态，模块页面不持有任何状态 —— 页面是纯函数，给定 `S` 的状态就能算出全部 HTML。
3. **写操作走事件总线**。`S.setRole()` / `S.setProject()` / `S.setLine()` 会 `emit('role'|'scope')`，`06-shell.js:507` 的订阅者自动调 `Shell.route()` 重渲染。**因此调完 setter 不要再手动 `Shell.route()`**，否则渲染两遍。

### 3.4 `CH`（04-charts.js，约 875 行）

```
基础     PAL, TONE, fmt, niceScale, color
图表     line, bar, donut, funnel, bars, flow, heat, gantt, timeline
内联     sparkSVG, ringSVG
交互     tipShow, tipHide, tipRow, bindTip, legend
重绘     redrawAll
```

`line` 通过 series 上的 `type:'bar'` 支持折柱组合；`bar` 通过 `stack:true` / `horizontal:true` 覆盖堆叠柱与横向排行；`gantt` 通过 item 上的 `type:'bar'|'mile'|'grp'` 混排阶段条、里程碑菱形与分组行。也就是 11 个方法覆盖 15 种图形。

> 其中 `ringSVG`（进度环）已实现并导出，但当前 59 个子页均未调用——进度统一用 `UI.progress` 条形。实际呈现 14 种图形，全站 119 处绘制调用；保留 `ringSVG` 作为备用组件。

全部图表画完会注册到内部 registry，`window.resize` 与侧栏折叠时统一 `CH.redrawAll()` 防抖重绘。tooltip 是全局单例 `#chartTip`，不是每个图表一个。

### 3.5 `UI`（05-ui.js，约 745 行）

### 3.6 `Shell`（06-shell.js，约 530 行）

```

paintNav, paintScope, paintNotice, help, init, PAGES
```

职责：hash 路由（`#/mod/sub` 与 `#/mod/sub/id`）、按角色渲染侧栏、面包屑与返回栈、全局搜索（⌘K）、角色切换、提醒中心、新建菜单、使用说明、无权限页。

内容区做了两个全局事件委托，模块页面可以直接写声明式属性、不用绑事件：

- `[data-go="mod/sub/id"]` → 跳转
- `[data-create="req.new"]` → 打开对应快捷新建表单

### 3.7 `P`（07-page.js，227 行）

```
权限     ed, permTip, viewTag
布局     gap, head, hero, statCards, kv, emptyMod, chart, $
下拉     sel, opts, lineOpts, projOpts, relOpts, memberNames
筛选     flt, setFlt, bindFlt
视图     viewBar, bindViews
导出     csv, word, wTable, scopeText
单元     pctCell, createBtn
```

这一层是**从 21 个模块里抽出来的重复套路**，是本方案里最有工程价值的一层。举例：

```js
P.permTip('requirements')   // 自动查 C.PERM_NOTE['requirements.' + 当前角色] 并渲染成说明条
P.createBtn('tasks', 'task.new', '新建任务')  // 无权限时自动灰化并加 title
P.word('周报', '项目周报', secs, meta)  // 自动加封面：组织 / 角色 / 口径 / 时间戳
```

`P.flt(mod, def)` 的三级合并是筛选条的核心：

```js
Object.assign({}, def,                                  // 页面默认
  C.viewOf(S.role(), mod).filter || {},                 // 角色默认视图
  S.pref(mod, 'filter', null) || {})                    // 用户上次的选择
```

## 四、模块页面的注册契约

20 个业务模块文件全部长成同一个样子：

```js
(function () {
  'use strict';

  Shell.page('requirements', {
    render: function (ctx) {
      // ctx = { mod, sub, id, el, nav }
      //   mod  当前模块 key
      //   sub  当前子页 key
      //   id   详情页 ID（无则空串）
      //   el   内容容器 DOM（已清空）
      //   nav  当前模块的导航配置
      if (ctx.id) return detail(ctx);
      switch (ctx.sub) {
        case 'pool':     return pool(ctx);
        case 'priority': return priority(ctx);
        // ...
      }
    }
  });

})();
```

**约束：**

1. 一个模块文件只调一次 `Shell.page()`，key 必须与 `C.NAV` 里的模块 key 一致
2. `render` 负责把 HTML 写进 `ctx.el`，然后绑事件、画图表
3. 页面是**幂等**的 —— 同一状态调两次 render 结果相同，因为它不持有状态
4. 不写裸 HTML 样式，一律用 `UI.*` / `P.*` / `CH.*`
5. 筛选条容器与表格容器必须是**兄弟节点**：

```html
<div class="toolbar" id="reqFlt">...</div>   <!-- 筛选，不重渲染 -->
<div id="reqTbl">...</div>                   <!-- 表格，局部重渲染 -->
```

> 这条约束是踩坑换来的：如果把表格套在筛选条内部，表格重渲染会连带销毁输入框，导致边打字边丢焦点。

## 五、新增一个模块要动哪几处

假设要加一个「竞品分析」模块，只对产品总监可见：

| 步骤 | 文件 | 改什么 |
|---|---|---|
| 1 | `01-config.js` `NAV` | 在总监分组里加一条 `{ key:'compete', label:'竞品分析', ico:'◭', subs:[{key:'list',label:'竞品库'},{key:'matrix',label:'能力矩阵'}] }` |
| 2 | `01-config.js` `PERM` | 加 `compete: { director:'full', pm:'none' }` |
| 3 | `02b-data.js` `blank()` | 在空库里加一个 `competitors: []` 集合（**只加空数组，不预置数据**） |
| 4 | `03-store.js` | 加 `competitors()` 取数方法，内部走 `scopeFilter` |
| 5 | 新建 `24-compete.js` | 按上一节契约写 `Shell.page('compete', {...})` |
| 6 | `index.html` | 在 20~23 之后加一行 `<script src="assets/js/24-compete.js">` |
| 7 | `08-guide.js` `G.TIP` | 加一条 `compete` 文案（是什么 / 什么时候用 / 第一步做什么），空态与功能地图都靠它 |
| 8（可选） | `01-config.js` `CREATE` + `99-app.js` | 若需要快捷新建，加一条配置 + 一个 `Shell.onCreate` |

**不需要动的：** 路由（自动）、侧栏（自动）、面包屑（自动）、权限拦截（自动）、功能地图（按 `C.navFor` 自动出卡）、全局搜索（除非要收录该实体）、CSS（复用现有组件类）。

> 第 7 步不是可选项。**开箱是空库**，新模块上线后使用者第一次进去看到的一定是空态；没有 `G.TIP` 就只剩一句「暂无数据」，等于把人晾在那儿。

这就是把"规则"集中在 `C`、把"套路"抽到 `P` 的回报。

## 六、CSS 拆分

| 文件 | 内容 | 改动频率 |
|---|---|---|
| `tokens.css` | 全部 CSS 变量：色彩、字号、间距、圆角、阴影、层级、布局尺寸 | 低。**任何色值/尺寸只允许在这里定义** |
| `layout.css` | 顶栏、侧栏、面包屑、内容区、栅格、响应式断点 | 低 |
| `components.css` | 40+ 组件类：表格、看板、甘特、泳道、时间线、热力、三色灯、抽屉、模态、表单… | 中。新增组件时追加 |
| `print.css` | A4 横向打印覆盖 | 极低 |

命名约定：组件根类用完整词（`.metric-card`），子元素用短前缀缩写（`.mc-val`、`.dh-title`、`.gs-item`）。不用 BEM 的双下划线 —— 在纯 CSS 无预处理器的前提下，短前缀更省字符且够用。

**角色主题的实现只有一处**：

```css
body[data-role="director"] { --c-accent: #4f46e5; ... }
body[data-role="pm"]       { --c-accent: #0e7490; ... }
```

`Shell` 切角色时只改 `body` 的这一个属性，全站几百处引用 `var(--c-accent)` 的地方同时变色。**没有任何 JS 参与配色**。

## 七、迁移到 Vue / React 的建议

这套结构是刻意为迁移留了口子的。按层给建议：

| 当前 | 迁移到 Vue 3 | 迁移到 React |
|---|---|---|
| `U` | 原样保留为 `utils/` 纯函数模块，几乎不改 | 同左 |
| `C` | 原样保留为 `config/` 常量模块 | 同左 |
| `DATA` | 换成 API 层（`save/load` 改成请求）。`blank()` 里的 28 个集合定义正好是**服务端表结构的第一版草稿**；`export/import` 保留为「导出备份 / 导入迁移」功能 | 同左 |
| `S` | 改写为 Pinia store：`state` 对应 `state`，取数方法对应 `getters`，`add/update/remove` 对应 `actions`，`onChange` 由响应式系统天然替代 | Zustand / Redux Toolkit；`onChange` 由 subscribe 替代 |
| `CH` | 保留为纯函数 `render(el, opts)`，用一个 `<Chart>` 包装组件在 `onMounted` 里调 | 同左，`useEffect` 里调 |
| `UI` | **逐个重写为 SFC**。`UI.table` → `<DataTable>`，`UI.drawer` → `<Drawer>`（用 Teleport） | 重写为函数组件，Drawer 用 Portal |
| `Shell` | 拆成 `App.vue` + `vue-router`；`Shell.page` 注册表 → 路由表；`Shell.go` → `router.push` | React Router 同理 |
| `P` | 拆成 composables：`usePermission` / `useFilter` / `useSavedView` / `useExport` | 拆成 hooks |
| `G` | 文案 `TIP` 原样保留为常量；`setupCard` / `emptyFor` 重写为 `<SetupChecklist>` / `<EmptyState>` 两个组件 | 同左 |
| 21 个模块 | 每个子页一个 `.vue` 文件，59 个页面组件 | 59 个页面组件 |

**迁移顺序建议：** `S` → `UI` → `Shell` → 模块页面。因为下层稳定后上层才好动，而 `U` / `C` 根本不用动。

**最值得保留的三个设计：**

1. **`C` 单点配置驱动导航与权限** —— 迁到任何框架都成立，且是这套系统"改一处、全站生效"的根源
2. **`scopeFilter` 统一口径** —— 角色切换只影响一个函数，而不是散在 59 个页面里各写各的过滤
3. **CSS 变量做角色主题** —— 比 JS 主题方案便宜一个数量级，且切换零闪烁

**最不值得保留的：** `P.head` / `P.sel` 这类"拼字符串"的辅助函数。它们存在只是因为原生 JS 没有模板系统；一旦有了 JSX 或 SFC template，它们应该直接消失。
