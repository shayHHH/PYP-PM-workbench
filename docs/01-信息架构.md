# 01 · 系统整体信息架构

## 一、一句话定位

**产品管理工作台**是一套面向产研组织的统一 Web 后台：一份数据、两种视角。产品总监看"多产品线的方向与结果"，项目经理看"单项目的执行与交付"，两者在同一套导航、同一套组件、同一份底层数据上工作。

---

## 二、四层架构

```
┌─────────────────────────────────────────────────────────────┐
│  L4  视图层    首页驾驶舱 · 21 个模块 · 59 个子页面          │
├─────────────────────────────────────────────────────────────┤
│  L3  能力层    图表引擎 CH · 组件库 UI · 页面助手 P · 引导 G  │
├─────────────────────────────────────────────────────────────┤
│  L2  逻辑层    数据仓库 S（口径过滤 / 派生统计 / CRUD 留痕）  │
├─────────────────────────────────────────────────────────────┤
│  L1  基础层    本地库 DATA · 配置 C · 工具 U                 │
└─────────────────────────────────────────────────────────────┘
```

**关键约束一**：视图层永远不直接读 `S.DB`，一律经过 `S.xxx()`。这保证了"切换角色 = 切换口径"这一核心机制在每一个页面上自动生效，无需页面各自实现。

**关键约束二**：L1 的 `DATA`（`02b-data.js`）是唯一和 `localStorage` 打交道的地方。开箱时它造一个**空库**——`COLLS` 定义的 28 个业务集合里有 27 个是空数组，没有任何预置数据；唯一例外是 `members`，预置「你自己」一条，否则所有负责人下拉框都是空的。`S` 的每一次 `add/update/remove` 之后同步调 `DATA.save()` 整库落盘。

---

## 三、业务信息域

系统把产研工作切分为 **6 个信息域**，20 个业务模块归属其中；另有 1 个非业务模块「上手与数据」独立于六域之外（见本节末）：

### 域 1 · 战略与规划（Why）
> 回答"我们要做什么、为什么做"

- **产品规划**（总监）— 产品线、路线图、OKR 映射、多线对比
- **用户反馈**（总监）— 反馈台账、聚类分析、影响面评估
- **经营复盘**（总监）— 月度/季度复盘、目标完成率、问题归因

### 域 2 · 需求与版本（What）
> 回答"要交付什么、什么时候交付"

- **需求管理**（公共）— 需求池、优先级、状态流转、PRD 归档
- **版本管理**（公共）— 版本计划、发布时间线、版本对比、版本复盘
- **需求变更**（PM）— 变更申请、影响评估

### 域 3 · 执行与进度（How）
> 回答"做到哪一步了、卡在哪里"

- **项目计划**（PM）— 阶段计划、里程碑、依赖关系
- **任务管理**（PM）— 任务列表、任务看板
- **进度跟踪**（PM）— 甘特图、延期分析、阻塞清单
- **交付管理**（PM）— 交付物清单、验收记录、文档归档

### 域 4 · 资源与协同（Who）
> 回答"谁在做、够不够人、跨部门顺不顺"

- **资源协调**（PM）— 人员安排、工时负载、跨部门协同
- **团队管理**（总监）— 成员列表、负载热力、协同效率
- **项目协同**（公共）— 协同看板、跨部门事项、协同动态
- **会议纪要**（公共）— 会议列表、Action 跟踪

### 域 5 · 风险与质量（Risk）
> 回答"有什么会出问题"

- **风险预警**（公共）— 风险台账、问题清单、趋势统计

### 域 6 · 度量与留痕（Evidence）
> 回答"结果如何、过程可查吗"

- **数据分析**（公共）— 核心指标、趋势、漏斗、留存
- **工作留痕**（公共）— 时间轴、类型统计
- **周报月报**（PM）— 周报、月报
- **待办中心**（公共）— 我的待办、个人笔记
- **仪表盘**（公共，双版本）— 驾驶舱首页

### 域外 · 上手与数据（Meta）
> 回答"这东西怎么用、我的数据在哪"

- **上手与数据**（公共）— 上手引导、功能地图、数据管理

它不承载任何业务实体，存在的理由只有一个：**开箱是空库，必须有人告诉你从哪下笔。** 三个子页各司其职——

| 子页 | 干什么 |
|---|---|
| 上手引导 `guide/start` | 上手清单（共定义 9 步，按角色过滤后总监 8 步、PM 6 步），打钩状态由真实数据量推导，不用手动点；外加「怎么用」与字段速查 |
| 功能地图 `guide/map` | 按 `C.navFor(role)` 渲染当前角色可见的全部模块（总监 14 张 / PM 17 张），每张写"是什么 / 什么时候用 / 第一步做什么"并带当前数据量，点卡片直达 |
| 数据管理 `guide/data` | 数据存在哪、什么时候会丢、导出 JSON / 导入 JSON / 清空、组织与我 |

同一套引导文案（`G.TIP`，覆盖全部 21 个模块）还被 `G.emptyFor(mod)` 复用到各模块的空态里，所以你在任何一个空页面上看到的都不是「暂无数据」，而是「这个模块解决什么问题、你的第一步该做什么」。

## 四、数据实体关系

```
产品线 Line
  └── 项目 Project
        ├── 阶段 Phase          ──> 里程碑 Milestone
        ├── 任务 Task           ──> 工时分配 Alloc
        ├── 需求 Requirement    ──> 变更 Change
        │                        └── PRD 归档
        ├── 版本 Release        ──> 交付物 Deliverable
        ├── 风险 Risk / 问题 Issue
        ├── 会议 Meeting        ──> Action Item
        ├── 跨部门事项 Cross
        └── 周报月报 Report

产品线级
  ├── 路线图 Roadmap / OKR
  ├── 用户反馈 Feedback
  ├── 经营复盘 Review
  └── 周指标 Metric（按周一条一条录，见下）

全局
  ├── 成员 Member（空库自带「你自己」一条，其余你自己加）
  ├── 工作留痕 Trace（由各实体变更自动生成，不需手工录）
  └── 待办 Todo（按 role 字段隔离）
```

**上面这张图没有标数量，因为开箱时每一个集合都是 0 条。** 数量取决于你录了多少。「数据管理」页会实时列出当前各集合的条数。

**建立顺序有依赖**：产品线 → 项目 → 成员 → 需求 / 任务 → 版本。跳着建不会报错，但下拉框会是空的——比如还没有产品线时去建项目，「所属产品线」就没得选。这也是上手清单排成那个顺序的原因。

**两类实体不用手录**：
- `Trace` 工作留痕由 `S.add / update / remove` 自动写入，你改什么它记什么。
- `Alloc` 工时分配由任务的负责人与工时字段派生，不是独立录入的表。

**`Metric` 周指标是唯一有固定槽位的实体**：`C.METRIC_SLOTS` 定义了 6 个 key（`arr / mau / renew / nps / ticket / sla`），因为 `13-analytics.js` 的看板与达标判断按这几个 key 组织。录入走顶栏「＋新建 → 指标数据」，一次填一个槽位在某个口径下某一周的值。槽位只给建议的名称 / 单位 / 格式，**目标值和实际值全部由你填，不预设任何数字**。

**关键字段**：几乎所有实体都带 `projectId` + `lineId` 双字段。这是"一份数据两种口径"的基础——`S.scopeFilter()` 对总监按 `lineId` 过滤，对 PM 按 `projectId` 过滤，同一个实体在两种视角下自动落到正确的集合里。

## 五、口径切换机制

| 角色 | 顶栏选择器 | 默认口径 | `scopeFilter` 行为 |
|---|---|---|---|
| 产品总监 | 产品线下拉（你已建的全部产品线，另有「全部产品线」一项） | 当前产品线 | 保留 `lineId === 当前线` 的记录；无 `lineId` 的记录通过 `projectId` 反查所属线 |
| 项目经理 | 项目下拉（你已建的全部项目） | 当前项目 | 保留 `projectId === 当前项目` 的记录 |

**特例处理**：
- 产品线级实体（路线图、OKR、用户反馈、经营复盘）在 PM 口径下自动降级为 `line` 口径——PM 也需要知道自己项目所属产品线的规划，只是不能编辑。
- 全局实体（成员、待办）不参与口径过滤；待办按 `role` 字段隔离。

## 六、权限模型

四态权限，定义于 `C.PERM[模块][角色]`：

| 态 | 含义 | 表现 |
|---|---|---|
| `full` | 完全权限 | 可见、可编辑、新建按钮高亮 |
| `limited` | 受限编辑 | 可见、部分操作可用、页面顶部有说明条 |
| `scoped` | 只读 | 可见、新建/编辑按钮灰化并带 tooltip，页面顶部有说明条 |
| `none` | 不可见 | 侧栏不渲染该模块；直接输入 hash 路由时渲染"无权限"说明页 |

**权限判断入口**：`C.canSee(mod, role)` / `C.canEdit(mod, role)`。页面内统一用 `P.ed(mod)` 与 `P.permTip(mod)`，不允许各页面自行硬编码角色判断。

## 七、导航层级

```
Level 0  顶栏          组织 / 系统名 / 口径选择器 / 全局搜索 / 提醒 / 新建 / 角色
Level 1  侧栏模块      21 个（按角色过滤后：总监 14、PM 17）
Level 2  子页面 Tab    59 个（公共 28 + 总监 13 + PM 18；
                       按角色过滤后：总监可见 41、PM 可见 46）
Level 3  详情          抽屉（Drawer）为主，少数用模态（Modal）
```

**路由规则**：`#/模块key/子页面key` 与 `#/模块key/子页面key/实体id`。刷新可还原，可复制分享。

## 八、跨模块联动

系统刻意保留了 8 条跨模块跳转路径，避免模块成为孤岛：

| 起点 | 动作 | 终点 |
|---|---|---|
| 需求池 | 点击关联版本 | 版本管理 · 版本计划 |
| 版本详情 | 点击需求数 | 需求管理 · 需求池（预置筛选） |
| 变更详情 | 点击"查看关联需求" | 需求管理 · 需求池 |
| 进度跟踪 · 甘特 | 点击任务条 | 任务管理 · 任务详情抽屉 |
| 资源协调 · 成员抽屉 | 点击"查看其任务" | 任务管理 · 任务列表（预置负责人筛选） |
| 会议详情 · Action | 点击 Action | 待办中心 |
| 风险台账 | 点击"关联项目" | 进度跟踪 |
| 全局搜索 | 回车 | 对应实体的详情抽屉 |

此外所有图表的 `onClick` 下钻默认行为是**回填当前页筛选条件**（而非跳页），保持用户上下文不丢失。
