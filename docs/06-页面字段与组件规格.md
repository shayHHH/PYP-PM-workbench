# 06 · 页面字段与组件规格

> 逐页给出**表格列 / 图表 / 筛选项 / 操作按钮 / 抽屉分区**。所有内容以 `assets/js/*.js` 实现为准。
>
> 通用约定见文末「附录 A · 组件契约」。

---

## 阅读约定

- **表格列**：按渲染顺序列出表头文案；`[方括号]` 表示该列**按角色条件显示**（来自 `C.VIEW[role][mod].cols`）
- **✅勾选**：该表开启 `select: true`，表头出现全选框，选中后浮出批量条
- **筛选项**：从左到右的工具条顺序；「关键词」一律为模糊搜索框，其余为下拉
- **导出**：`CSV` = `U.exportCSV`；`Word` = `P.word`（HTML 伪装 `.doc`）；`打印` = `U.printPage`（A4 横向）

| 上手清单 | `G.setupCard(false)` | 共定义 9 步，**按角色过滤后总监看到 8 步、PM 看到 6 步**，见下表 |
| 当前角色视角 | `S.roleObj()` | 数据口径 / 独有模块 / 怎么切换 / 为什么要两个 |
| 常用操作速查 | 静态 | ⌘K、顶栏＋新建、表格、看板、图表、Esc |
| 数据存在哪里 | 静态 + `UI.notice('warn')` | 会自动保存吗 / 怎么备份 / 怎么换电脑 / 里面有假数据吗 |

**上手清单**（`G.steps()`）共定义 9 步，末尾按 `s.roles.indexOf(role) >= 0` 过滤。每一步的打钩状态**由真实数据量推导，不能手动勾选**：

| key | 步骤 | 完成判据 | 动作 | 可见角色 |
|---|---|---|---|---|
| `org` | 填组织抬头和你的名字 | `org.name` 非空且已改过默认值 `'我的组织'` **且** `S.me().name` 非空 | 打开「组织与我」表单 | 两者 |
| `line` | 建第一条产品线 | `cnt.lines > 0` | `line.new` | 仅总监 |
| `project` | 建第一个项目 | `cnt.projects > 0` | `project.new` | 两者 |
| `member` | 把常打交道的人录进成员表 | `cnt.members > 1` | `member.new` | 仅总监 |
| `req` | 录第一条需求 | `cnt.requirements > 0` | `req.new` | 两者 |
| `release` | 排第一个版本 | `cnt.releases > 0` | `release.new` | 仅总监 |
| `task` | 拆第一批任务 | `cnt.tasks > 0` | `task.new` | 仅 PM |
| `risk` | 登记一条风险或记一次会议 | `cnt.risks > 0` **或** `cnt.meetings > 0` | `risk.new` | 两者 |
| `backup` | 导出一份备份 | `DATA.setupFlags().backup` | `DATA.exportJSON()` + `markStep('backup')` | 两者 |

**过滤后**：总监 8 步（`org / line / project / member / req / release / risk / backup`），PM 6 步（`org / project / req / task / risk / backup`）。进度条 `G.progress()` 的分母是**过滤后的步数**，所以 PM 的 100% 是 6/6 而不是 6/9。

> 两处阈值值得注意：
> - `member` 判 `> 1` 而不是 `> 0`——`DATA.blank()` 自带「你自己」一条成员记录，必须真的加了同事才算完成。
> - `risk` 是**或**关系，风险和会议记哪个都算，因为这一步想让你体验的是「登记一次就会自动流转到别处」，风险上首页、会议 Action 进跟踪列表，二者等效。

## 20.2 上手与数据 · 功能地图 `#/guide/map`

按 `C.navFor(role)` 分组渲染模块卡——所以总监看到 14 张、PM 看到 17 张，越权模块不出现。

每张卡片（`.gmc`）四段：模块名 + 图标 → **是什么 / 什么时候用 / 第一步做什么**（取自 `G.TIP[mod]`）→ 子页名列表 `.gmc-subs` → 当前数据量 `G.countOf(mod)`。整卡可点，跳该模块的第一个子页。

> `G.TIP` 覆盖**全部 21 个模块**（`08-guide.js:20–146`），`dashboard` 与 `guide` 自身也各写了一段——所以功能地图上不会出现"有卡片却没有说明"的缺口。这两条的差别只在动作按钮：`dashboard` 给的是 `go: 'guide/start'`（跳上手引导）而非 `create`，因为首页的内容是自动汇总的，没有"直接新建一条"的动作。

## A.1 数据表格 `UI.table`

签名是 **`UI.table(hostEl, opt)`** —— 第一个参数是宿主 DOM 节点，不是配置对象。

```js
UI.table(ctx.el.querySelector('#reqTbl'), {
  cols: [{ k, t, w, cls, align, sortable, sortVal(r), render(r), th }],
  rows, page, pageSize, sort: { k, desc },
  select: true,                  // 开启勾选列
  index: true,                   // 显示行序号列
  bulk: [{ t: '批量动作名', cls, fn(picked) }],
  rowCls(r), onRow(r), onAct(act, r), onSort(s),
  toolbar, onToolbar(el),
  compact, maxH,
  empty, emptyAct, footNote
})
```

- `w` 支持数字（自动补 `px`）或字符串
- `sortable` 默认为真，要关闭需显式写 `sortable: false`
- `sortVal` 用于自定义排序键（如按状态字典顺序而非拼音）
- `th` 可覆盖表头单元格的渲染
- `maxH` 给表格体加最大高度并内部滚动，`compact` 收紧行高
- 勾选后底部浮出批量条，显示「已选 N 项」与全部 `bulk` 动作

## A.3 筛选条

```html
<div class="toolbar" id="xxFlt">…筛选控件…</div>
<div id="xxTbl">…表格…</div>
```

两者必须是**兄弟节点**——表格重渲染只替换 `#xxTbl` 的内容，筛选框的输入焦点与光标位置得以保留。

## A.4 详情抽屉 `UI.drawer`

```js
var d = UI.drawer({ title, sub, body, foot, wide, onOpen(h), onClose });
```

- 三种关闭方式：ESC / 点遮罩 / 点关闭按钮
- `foot` 中带 `data-close` 属性的按钮由抽屉内部自动绑定关闭
- 详情路由 `#/mod/sub/id` 刷新后可自动重开抽屉

## A.5 权限门禁

页面内一律使用：

```js
P.ed('模块key')        // 是否可编辑 → 决定按钮是否灰化
P.permTip('模块key')   // 渲染页面顶部的权限说明条
```

不允许任何页面自行硬编码 `role === 'director'` 之类的判断。
