# 04 · 项目经理角色首页布局

> 路由：`#/dashboard/main`（角色 = 项目经理）
> 实现：`assets/js/10-dashboard.js` → `PM_BLOCKS`；编排来自 `C.HOME.pm`；指标来自 `S.homeMetrics()` → `METRIC_DEF`
> 与总监首页**同一个页面文件、同一套组件**，仅编排数组与取数函数不同。

---

## 一、设计意图

PM 首页要回答的是"今天我该做什么"，因此与总监首页有三点根本差异：

1. **粒度下沉到任务**：最小单位是一条任务、一个里程碑、一个交付物，而不是产品线。
2. **时间视野收窄到本周**：没有 26 周趋势图，取而代之的是"本周交付"和"今日待办"。
3. **首页可写**：今日待办的复选框可以直接勾选完成，是全站唯一在首页做写操作的地方——因为"勾掉一件事"是 PM 每天最高频的动作，不该逼他跳三层页面。

四个阅读层次：

| 顺序 | 问题 | 对应区域 |
|---|---|---|
| 1 | 我这个项目现在什么状态？ | 角色横幅 |
| 2 | 关键数字健康吗？有没有红灯？ | 6 张指标卡 |
| 3 | 阶段推进到哪、本周要交什么？ | 阶段进度 + 本周交付 |
| 4 | 我今天做什么、任务盘子长什么样、谁被卡住了、会上答应的事办了吗？ | 待办 + 任务分布 + 阻塞延期 + Action Item |

## 三、A 区 · 角色横幅

```
┌──────────────────────────────────────────────────────────────────────┐
│ 我，下午好　·　项目经理视角                        ┌────┬────┬────┐ │
│ 单项目执行视角 · 计划、任务、风险与交付            │  n%│  n │  n │ │
│ [当前项目：<你选中的项目>] [项目经理 <你的名字>]   │项目进度│在办任务│延期任务││
│ [<项目起始日> ~ <项目结束日>]                      └────┴────┴────┘ │
└──────────────────────────────────────────────────────────────────────┘
```

| 元素 | 内容 | 取数 |
|---|---|---|
| 主标题 | `{用户名}，{问候语}　·　项目经理视角` | `C.ROLES.pm.user.name` |
| 副标题 | 单项目执行视角 · 计划、任务、风险与交付 | `C.ROLES.pm.slogan` |
| 标签 1 | 当前项目：`{项目名}` | `S.curProject().name` |
| 标签 2 | 项目经理 `{PM 名}` | `project.pm` |
| 标签 3 | `{开始日} ~ {结束日}` | `project.start` / `project.end` |
| 右侧统计 1 | 项目进度（%） | `S.projectStat(pid).progress` |
| 右侧统计 2 | 在办任务 | `st.taskOpen` |
| 右侧统计 3 | 延期任务 | `st.taskDelay` |

横幅底色随 `body[data-role="pm"]` 切换为青色系（`--c-accent: #0e7490`）。**这是两套首页唯一的色彩差异**——版式、圆角、间距、字号完全一致，因此切换角色时不会产生"换了个产品"的割裂感。

## 四、B 区 · 6 张指标卡

| # | key | 卡面标题 | 数值 | 单位 | 副文案 | 图标 | 语气 | 点击去向 |
|---|---|---|---|---|---|---|---|---|
| 1 | `projProgress` | 当前项目进度 | `st.progress × 100` | % | `{项目名}` | ◫ | doing（青） | `#/progress/gantt` |
| 2 | `milestoneRate` | 里程碑完成率 | `已完成 / 总数` | % | `M/N 已完成 · K 延期` | ◈ | **动态**：有延期 → 琥珀，否则绿 | `#/plan/phases` |
| 3 | `openTasks` | 未完成任务 | `st.taskOpen` | 个 | `共 N 个任务 · 已完成 M` | ☑ | 默认 | `#/tasks/list` |
| 4 | `delayTasks` | 延期任务 | `st.taskDelay` | 个 | 有延期→`需立即介入`，否则`无延期` | ⏱ | **动态**：>0 红，=0 绿 | `#/progress/gantt` |
| 5 | `projRisks` | 未关闭风险 | `st.riskOpen` | 项 | `N 项高风险` | ⚠ | **动态**：有高风险 → 红，否则琥珀 | `#/risks/ledger` |
| 6 | `blockers` | 阻塞事项 | `st.taskBlocked` | 个 | 有阻塞→`平均阻塞 N 天`，否则`当前无阻塞` | ⛔ | **动态**：>0 红，=0 绿 | `#/progress/blocked` |

**与总监卡片的关键差异**：PM 的 6 张卡里有 **4 张会自己变红**（2/4/5/6），总监只有 1 张。这是刻意的——PM 首页要能"报警"，总监首页要能"体检"。

## 五、C 区 · 六个内容块

### C1 · 项目阶段进度（通栏）

- **标题栏**：`◫ 项目阶段进度` / 副标题 `{项目名} · {起} ~ {止}` / 右上角 `阶段划分 →`（跳 `#/plan/phases`）
- **上半：横向进度条组** `CH.bars`，每个阶段一条
  - 文案：`{进度}% · {状态}`
  - 条色：已完成 → 绿，进行中 → 青（doing），其余 → 灰（idle）
  - 点击 → `#/plan/phases/{phaseId}`
- **下半：甘特图** `CH.gantt`（高 260px），两类行混排
  - `type:'bar'` 阶段条，宽度 = start~end，内部填充进度百分比
  - `type:'mile'` 里程碑菱形，落在 `date` 当天；已延期→红，已完成→绿，其余→琥珀
  - 点击阶段条 → `#/plan/phases/{id}`；点击菱形 → `#/plan/milestones/{id}`

> 阶段条 + 里程碑菱形放在同一张甘特里，是为了让"这个阶段还剩多少"和"这个阶段末尾要交什么"在同一根时间轴上对齐。

### C2 · 本周交付

- **标题栏**：`◷ 本周交付` / 副标题为本周日期区间
- **主体**：`S.weekDelivery()` 聚合本周内的 4 类交付节点，最多 9 条
  - 里程碑 ◈ / 交付物 ⬓ / 版本 ⬢ / 任务 ☑
- **每行结构**：`[类型标签] 标题（截断 24 字）` + 次行 `负责人 · 状态标签` + 右侧到期徽标
- 空态：「本周暂无交付节点」

### C3 · 我的待办（**可写**）

- **标题栏**：`✓ 我的待办` / 副标题 `共 N 项未完成` / 右上角 `＋ 新增`（直接拉起 `todo.new` 表单，不跳页）
- **排序**：先按优先级，同优先级按截止日升序；取前 8 条
- **每行结构**：行首复选框 + 标题 + 次行 `优先级标签 · 来源` + 右侧到期徽标
- **交互**：勾选任一复选框 → 该待办状态置为「已完成」、清除逾期标记 → `UI.toast('待办已完成')` → `S.emit('data')` 触发全站重渲染（首页卡片计数同步变化）
- 空态：「今日待办已清空」（✓ 图标）

> 事件绑定在容器 `#homeTodo` 上做委托，而不是逐行绑定，因此重渲染后无需重新绑定。

### C4 · 任务分布概览

- **标题栏**：`☑ 任务分布概览` / 副标题 `共 N 个任务` / 右上角 `任务看板 →`（跳 `#/tasks/kanban`）
- **主体**：`.grid.g2` 并排两图
  - 左：`CH.donut` 任务状态环，中心显示任务总数，扇区按 `C.DICT.taskStatus` 顺序排列、按状态语气取色
  - 右：`CH.bar`（横向）任务类型分布，按 `C.DICT.taskType` 顺序
- 两图点击均跳 `#/tasks/list`

### C5 · 阻塞与延期

- **标题栏**：`⛔ 阻塞与延期` / 副标题「需要立即介入」 / 右上角 `阻塞项 →`（跳 `#/progress/blocked`）
- **筛选**：`status === '已阻塞'` **或**（已逾期且未完成），按截止日升序，取前 8 条
- **每行结构**：
  - 图标：已阻塞 ⛔ / 仅逾期 ⏱
  - 标题（截断 26 字）
  - 描述行：已阻塞显示红色「阻塞」标签 + 阻塞原因；仅逾期显示琥珀「延期 N 天」标签
  - 次行：负责人头像 + 任务类型
  - 右侧：到期徽标
- 点击 → `#/tasks/list/{taskId}`（直开任务详情抽屉）
- 空态：「当前无阻塞与延期任务」（✓ 图标）

### C6 · 会议 Action Item

- **标题栏**：`▤ 会议 Action Item` / 副标题 `未完成 N 项` / 右上角 `全部跟踪 →`
- **筛选**：排除「已完成 / 已取消」，按截止日升序，取前 8 条
- **每行结构**：Action 正文（截断 28 字） + 次行 `来自 {会议标题}` + 负责人头像 + 右侧 `状态标签 + 到期徽标`
- 点击 → `#/meetings/actions/{actionId}`
- 空态：「暂无待跟进 Action Item」

> 把 Action Item 提到首页，是为了闭合"开会 → 定事 → 没人管"这个最常见的项目管理断点。

## 六、D 区 · 快捷新建

`C.ROLES.pm.quick` 的 6 个磁贴：

| # | key | 图标 | 磁贴文案 | 落位模块 |
|---|---|---|---|---|
| 1 | `task.new` | ☑ | 任务 | 任务管理 |
| 2 | `meeting.new` | ▤ | 会议纪要 | 会议纪要 |
| 3 | `risk.new` | ⚠ | 风险登记 | 风险预警 |
| 4 | `change.new` | ⇄ | 变更申请 | 需求变更 |
| 5 | `delivery.new` | ⬓ | 交付物 | 交付管理 |
| 6 | `report.new` | ▦ | 周报 | 周报月报 |

与总监的 6 项对比：`meeting.new` 与 `risk.new` 两项重合（协作与风险是两个角色共同的日常动作），其余 4 项完全不同。

## 七、两套首页的实现对照

| 项 | 总监 | PM |
|---|---|---|
| 编排来源 | `C.HOME.director` | `C.HOME.pm` |
| 区块字典 | `DIR_BLOCKS`（6 个函数） | `PM_BLOCKS`（6 个函数） |
| 绘图入口 | `drawDirector()` | `drawPM()` |
| 使用的图表 | `CH.line`(组合) / `CH.bars` / `CH.funnel` / `CH.line`(多线) | `CH.bars` / `CH.gantt` / `CH.donut` / `CH.bar` |
| 数据口径 | `S.xxx('line')` 显式按产品线 | `S.xxx()` 默认按当前项目 |
| 首页写操作 | 无 | 待办勾选 |

页面注册只有一处：

```js
Shell.page('dashboard', { render: function (ctx) {
  var role = S.role();
  var BL = role === 'director' ? DIR_BLOCKS : PM_BLOCKS;
  ctx.el.innerHTML = banner() + metrics() + '<div class="grid g2">' + blocks + '</div>' + quickPanel();
  if (role === 'director') drawDirector(); else drawPM();
}});
```

这一段是整套"一套后台、两种视角"设计的缩影：**分支只在编排层，不在组件层，也不在数据层**。
